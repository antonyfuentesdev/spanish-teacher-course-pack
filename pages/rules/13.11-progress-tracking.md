What the bot records, how progress is shown and how learners move up.

## Storage (format v2)

<b>Where everything is recorded:</b> the table "Where progress lives" in the Learning plan overview says where every record goes and when. This page defines the exact file format, the write procedure and the design assumptions with their built-in fallbacks.

- <b>Progress file:</b> <code>/workspace/spanish-teacher/progress.md</code> on the bot's own computer, plain markdown, one file per learner copy. It is the <b>source of truth</b> for progress, evaluations and exam results
- <b>Archive:</b> <code>/workspace/spanish-teacher/progress-archive.md</code> holds retired review items (step Done), same columns plus a Retired date, so the live queue stays small (about 2,400 active items by C1, 13.1)
- <b>Daily backups:</b> <code>/workspace/spanish-teacher/backups/progress-YYYY-MM-DD.md</code>, one per day, last 14 kept
- <b>Reserved names:</b> only the tutor bot writes <code>progress.md</code>, <code>progress-archive.md</code> and <code>backups/</code>. No other Bot and no design file may use or write those names (all Bots on an account share one computer)
- <b>Memory:</b> a short summary only: level, current topic, top errors, next review date, plus the learner profile facts. On conflict the file wins
- <b>Created fresh at intake</b> on each copy (intake chat); the file is not copied with the template
- Only Grok Bot's built-in features; no external service, database app or spreadsheet. A plain file needs no installed software
- <b>Template copies:</b> each learner's copy runs on that learner's own computer; one tutor copy per learner account

## Write procedure (every write)

1. Read the whole file; check the schema line says <code>v2</code>
2. Build the new version in memory of the run; write it to <code>progress.tmp.md</code>
3. Validate the temporary file: schema line present; title line <code># Spanish Teacher progress</code>, the seven section headings in order and all six table headers exactly as below; IDs unique and in order; no table has fewer rows than before (except Review queue, which shrinks only by rows moved to the archive); every Milestones row cites IDs that exist (Assessments IDs; Encouragement rows cite the Sessions or Assessments IDs that triggered them); every Assessments row has an Evidence entry (for a skipped placement, the learner's answer)
4. If no backup exists for today, copy the current <code>progress.md</code> to <code>backups/progress-YYYY-MM-DD.md</code> and delete backups older than the last 14
5. Replace <code>progress.md</code> with the temporary file. If validation fails, keep the old file, write nothing, and tell the learner in chat that the update needs a retry
6. <b>No duplicates:</b> every Sessions row is keyed by the call's start time (ISO 8601 with time-zone offset). If that key is already in the file, the call is skipped. Assessments are keyed by Session ID + Type + Form

## Design assumptions and built-in fallbacks (no test step)

These are design assumptions. The system is designed to work whether or not each assumption holds: every fallback below is built in and always on, and the voice service is trusted to behave as documented. Nothing may depend on an assumption silently.

| Design assumption | If it holds | Built-in fallback (always on) |
| --- | --- | --- |
| <b>A1.</b> During a live voice call the bot can use memory or read the progress file | The bot picks the topic, due items and retakes itself | <b>Next session brief:</b> before each planned study day a routine posts in chat the topic, session number, up to 8 due items per lesson, pending retakes and gate status. The learner starts the call from that chat; the bot opens with "¿Seguimos con \[tema\], sesión \[n\]?" and the learner confirms |
| <b>A2.</b> Something runs the Progress update after each call | The file is written right after the call | The update no longer depends on the learner. (1) The <b>daily reconcile</b> routine writes any missing rows (by key) from the call transcript; (2) the <b>next session's opening step</b> (next session brief, or the first chat turn) checks for an unsaved call and saves it first; (3) the learner <i>may</i> type or say "listo" to save sooner, but forgetting it costs nothing. See <b>Pending results</b> below |
| <b>A3.</b> A routine can read voice-call transcripts | Reconcile rebuilds missing Sessions rows from transcripts | Reconcile asks the learner in chat for a 3-line summary of the missed call and writes the row with Notes "reconstructed, no transcript"; no assessment is recorded from a reconstructed row; a check taken in that call becomes a <b>pending result</b> (below) and is never silently dropped |

<b>Pending results (no lost checks)</b>

- <b>In the call:</b> at the end of every check the bot says the provisional result aloud with 2–3 evidence quotes ("Provisional: 8 of 10. You said «me gustan las uvas»…"), so the transcript holds the score and its evidence. A spoken "listo" counts the same as a typed one
- <b>Saving:</b> the Progress update, the daily reconcile or the next session's opening step, whichever runs first, scores the check from the transcript with the second pass (13.9 §6) and writes the Assessments row and its Evidence. The date is the call's date, so spacing rules are unaffected
- <b>Told to the learner:</b> the next session opens with the result: "Your topic 2 check is saved: 8 of 10, passed."
- <b>If no transcript can be found</b> within 7 days: no score is ever recorded from memory (integrity). The bot tells the learner and offers an immediate re-sit on the <b>next form</b>, with the same attempt number. It is not counted as a retake, needs no 2-day wait and is flagged "re-sit, transcript lost" in Flag. The lesson time is kept as a reconstructed Sessions row
- The weekly summary lists any result still pending, so nothing stays open silently

## File template (schema v2)

The file starts with this header, then the six tables in this order. Dates and times are ISO 8601 with the learner's time-zone offset. One field per cell. A dash (–) means empty. IDs never change and are never reused.

```javascript
# Spanish Teacher progress
Schema: v2 · Learner: Laura · Time zone: America/Costa_Rica · Created: 2026-10-21T18:05-06:00
```

- <b>Section headings:</b> each table sits directly under its own heading line, in this order: <code>## Profile</code>, <code>## Sessions</code>, <code>## Assessments</code>, <code>## Evidence</code> (the evidence blocks, right after the Assessments table), <code>## Review queue</code>, <code>## Milestones</code>, <code>## Weekly log</code>
- <b>Created empty at setup:</b> course setup writes the title, the schema line with <code>Learner: –</code> and <code>Time zone: –</code>, the seven headings and the six empty tables (header rows only), before the learner has answered anything. The intake chat then fills Learner and Time zone in place once the learner gives a name and confirms the timezone; until then times use the computer clock's offset. The header's Learner and Time zone, the Profile rows and the Review queue rows are the only values updated in place

## Session summary

<b>Spoken (3 lines, about 20 seconds)</b> — no grammar terms at A1–B1; in English at A1 (example in Learner-facing words below):

> "Hoy pediste cosas a otra persona: «quiero que venga». Muy bien: te corregiste dos veces. Para la próxima: «llame», no «llama». Nos vemos el jueves."

<b>Posted in chat (full)</b>; headings in Spanish from B1, in English with the Spanish beside them at A1–A2. It leads with the learner's progress in things they can see (level, topics, hours); Overall % appears in the weekly summary, not after every call:

## Progress percentages (what the learner sees)

The learner sees three things, never a target date: <b>(1) current CEFR level</b>, <b>(2) percent progress within that level</b>, <b>(3) percent progress through the whole plan, A1 → C1</b>. Both percentages are capped so they cannot reach 100% before the gates below are met and recorded.

<b>(1) Current level</b> = Profile "Current level": set by the Placement row, then by each Level up Milestones row.

<b>(2) Level %</b> = round down (45 × T + 30 × H + 10 × C + 15 × E)

- T = topics at this level passed or fast-tracked (Assessments, Topic check, Result Pass) ÷ topics in the level (A1, A2: 6; B1, B2, C1: 12)
- H = lesson hours at this level (Sessions, Type Lesson or Consolidation, Level = current) ÷ the level's minimum lesson hours (table below), capped at 1
- C = consolidation sessions done at this level (Sessions, Type Consolidation) ÷ required (2 per course)
- E = 1 only when the Level up Milestones row exists, otherwise 0. So Level % stops at 85% until the level exam is passed, the second scoring pass agrees and the Level up row is written

<b>(3) Overall %</b> = round down (95 × (sum of plan hours of completed levels + plan hours of current level × Level % ÷ 100) ÷ 328 + 5 × G)

- Plan hours per level (13.1): A1 32, A2 32, B1 76, B2 88, C1 100; total 328
- Completed level = a Level up Milestones row exists, or the level was skipped by placement (reported as "credited by placement")
- G = 1 only when the Graduation Milestones row exists. So Overall % stops at 95% until graduation

<b>Where and when:</b> computed by the Progress update from Sessions, Assessments and Milestones; written to the Sessions row (Level %, Overall %) and to each Weekly log row. Level % (with topics done and lesson hours) is in the chat summary after every call; <b>Overall % is shown in the weekly summary</b> and whenever the learner asks, always with its one-line meaning, because it moves slowly over a 328-hour plan. A percentage is never rounded up, estimated or raised on request.

<b>Time estimates are internal.</b> The duration table in 13.1 (3 / 6 / 10 h a week) is a side metric for the bot: sanity checks and spotting rushing. It is never shown to the learner, never given as a promise or a target date, and never turned into months, weeks or a range, even when the learner asks (see "How long will it take?" in Motivation below).

## Motivation and milestone messages

Early progress must feel real even though Overall % moves slowly.

- <b>After every call:</b> level, topics done ("2 of 6"), lesson hours at this level ("9 of 24") and Level %
- <b>Weekly summary:</b> learning hours this week and to date ("all of it helps your fluency"), weeks on plan, writing tasks done (typed track), Overall % with its meaning
- <b>Milestone messages</b> (once each; written as an Encouragement Milestones row so they are never repeated): first lesson done; first topic passed ("You can now introduce yourself and give your phone number in Spanish": the matching can-do line); each course up; 10, 25, 50, 100 and 200 learning hours; 4 weeks on plan; each level up, with that level's can-do list below
- <b>"How long will it take?" (only when asked):</b> no time estimate. The bot explains Level % (how far through the current level) and Overall % (how far through the whole course, A1 to C1), then says what is left in the current level in plain counts: topics left, lesson hours still needed for the exam gate, consolidation sessions left, the 3-week minimum at the level and the previous level's one-month check. Example at A1: "You're at 40% of A1 and 3% of the whole course. To finish A1 you have 4 topics and 15 lesson hours left, then the A1 exam. The pace is up to you; more lessons a week moves it faster." Never a forecast in months, weeks or dates; the 13.1 duration table stays internal

## Gates (anti-rush)

Gates rest mainly on <b>lesson hours, session counts, spacing between exams and retention re-checks</b>. Calendar minimums are modest, so a learner who studies every day can move faster, but nobody can finish a level, or the plan, in a week. Every gate is checked from the progress file and written in the Milestones "Gate check" cell. The bot states gate status aloud when asked or when a check is refused, in English at A1–A2 ("You can take the A2 exam after 24 lesson hours; you have 18") and in Spanish from B1 ("Puedes hacer el examen de B1 cuando completes 57 horas de clase; llevas 40"). At intake the learner hears a one-minute "how this course works" explanation of the caps (intake chat), and can ask "What are the rules?" any time.

<b>Minimum lesson time per level before its exam</b> (lesson hours = Lesson + Consolidation sessions at that level; 75% of the level's plan hours, 25% for a level the learner was placed into). <b>Placed level</b> = a level the placement test put the learner into <i>above A1</i>; a learner placed at A1 follows the full A1 minimum

| Level | Plan lesson hours | Minimum lesson hours (sessions of 30 min) | If placed at this level |
| --- | --- | --- | --- |
| A1 | 32 | 24 h (48) | 8 h (16) |
| A2 | 32 | 24 h (48) | 8 h (16) |
| B1 | 76 | 57 h (114) | 19 h (38) |
| B2 | 88 | 66 h (132) | 22 h (44) |
| C1 | 100 | 75 h (150) | 25 h (50) |

<b>1. Daily and weekly caps</b>

- At most 2 new-content lesson sessions per calendar day; only these count toward lesson hours (plus, at a placed level only, the extra time in §5). Extra calls that day are review or free talk (learning hours only)
- At most 1 topic check per day, at most 1 exam paper group per day, at most 3 fast-tracks per week

<b>2. Topic</b>

- Topic check after the topic's lesson sessions (13.2), never on the same day as its last new-content session
- Pass at 60% (6/10). At most 2 retakes per topic, each on a different form, at least 2 days apart. Normal order: regular check Form A, retakes Form B, then Form C. After a failed fast-track (which used Form A): regular check Form B, retakes Form C, then Form D, so no form is reused for that learner. After a third fail: 2 recycle sessions, then one final sitting on Form D if the learner has not used it; only a learner who has already used all four forms gets the least recently used form, flagged "Reused form" (13.9 §2)
- Session-10 layout (A1–A2; last session at higher levels): 10 min warm-up review, about 8 min check in test mode, then feedback and free chat (13.2)
- No hints during a check: the correction ladder is off; feedback comes after scoring

<b>3. Fast-track</b>

- Optional, offered at the <b>start of session 1</b>, before any teaching, once per topic, at most 3 a week. The bot says what it is and that saying no is fine (Learner-facing words). It is not offered to a self-declared beginner (skipped placement) during course A1.1; they can still ask for it
- Needs 8/10 or more <b>and</b> Part B 4/4 on Form A. Items marked "seen" are seen only by learners who did the sessions; for a fast-tracker every item is new, which is the point: it tests whether the topic is already known
- Below 8/10 simply means "learn this topic normally": no penalty, the score is recorded, and the regular check later uses Form B
- Three of the topic's items are added to the queue at step 3 (due in 7 days); missing 2 of the 3 re-opens the topic
- <b>Placement confirmation:</b> if the learner's first two assessed results at a placed level (fast-track or topic check) are both under 6/10, the bot <b>offers</b> a move down one level. The learner decides; nobody is moved automatically. A Move down Milestones row is written only if the learner accepts; if they decline, they continue at the placed level and the offer is noted in the Gate check. The bot explains this before the first fast-track. One fast-track under 8/10 never moves anyone down

<b>4. Course</b>: all 3 topics passed or fast-tracked and both consolidation sessions done → Course up

<b>5. Level exam eligibility</b> (all needed)

- All topics of the level passed or fast-tracked; all consolidation sessions done
- Minimum lesson hours and sessions (table above). <b>At a placed level</b> (changed) the minimum counts Lesson, Consolidation and Typed minutes, topic-check and fast-track time, and up to 1 Review session a day. Fast-tracking leaves topic sessions untaken, so before each fast-track the bot checks the hours: if passing it would leave the minimum out of reach of the remaining topics, it says so. When every topic is done and hours are still short, the bot schedules <b>practice sessions</b>: the untaken sessions of fast-tracked topics, weakest topic first, which count as Lesson. The learner always hears exactly how many hours are left and what counts
- The level's exam papers are in 13.13 Exam papers
- At least 3 weeks since Level start (placed learners too)
- The previous level's 30-day retention check passed (so two level-exam passes are always at least 30 days apart)
- The exam includes a <b>retention set</b>: 10 items of this level created at least 21 days earlier (queue or archive); 7/10 or more is required as well as the paper rule (13.9 §3)

<b>6. Level exam retakes</b>: failed group only, at least 10 days later, on a new form; at most 3 sittings, then a 4-week review cycle before the next sitting

<b>7. After each level pass</b>: 30 days later the <b>one-month check</b>: 10 minutes, 10 items from that level, pass 6/10. 60% or more → Retention passed. Under 60% → a <b>refresher</b>: 2 consolidation sessions, then a re-check; the next level exam waits until it passes (Milestones type Refresher due). The badge is never marked or taken away. The learner is told about the one-month check when the level is passed. Not to be confused with the <b>exam memory check</b> inside each level exam (§5, 7/10)

<b>8. Graduation</b> (all needed; checked and listed in the Graduation Milestones row)

- C1 level exam passed (Group 2; plus Group 1 for the four-skill badge), with both scoring passes recorded
- C1 minimum lesson hours (75 h; 25 h if placed at C1) and all 12 C1 topics passed or fast-tracked
- C1 one-month check passed, and no refresher open at any level
- C1 graduation oral passed under the 13.9 §4 rule, with both scoring passes
- So a learner placed straight into C1 still needs at least 25 lesson hours, 3 weeks at C1, the exam, a 30-day retention check and the oral: about 8 weeks at the very least (25 days of lessons at 2 a day, the exam, then 30 days to the retention check)

<b>9. Never early</b>

- The bot never says a level is passed, the plan is complete or the learner has graduated until the matching Milestones row is written after the second scoring pass
- A learner's request can never create, raise or skip an Assessments or Milestones row, or change a percentage

<b>10. Other rules</b>

- <b>Locked levels:</b> placement and promotion cannot enter a level whose topics are not in this course pack (13.12 Topic materials). Until then the learner works at the highest ready level, or has free conversation, labelled as such; it counts only toward learning hours. All 48 topics are in this course pack, so no level is locked now; this rule applies only if a topic page is ever withdrawn. In that case the bot says plainly that the course is temporarily closed and offers free conversation, counted as practice time
- <b>Exam papers:</b> a level exam runs only while its papers are in 13.13 Exam papers. All levels have papers; only if a paper is ever withdrawn from the course pack does the bot tell the learner the exam is temporarily unavailable and that their progress is saved
- <b>Pronunciation</b> is never a promotion or pass condition, by design: the course does no audio-rating test, and pronunciation is coached and reported for feedback only
- <b>Moving down:</b> two topic checks in a row under 40% → the bot offers to go back one course
- <b>Pace check (internal):</b> when it writes the weekly report, the bot compares scores, lesson hours and learning hours with the internal duration table in 13.1 and flags rushing or a stall; a stall gets an offer to change the study plan. It is not a learner target and is never shown as a time estimate
- Every promotion, badge and level-up is a Milestones row citing its Assessments IDs (Encouragement rows cite Sessions or Assessments IDs); the memory summary's level and topic are then updated

## Can-do exit statements

A learner who passes each level can (speaking and listening; reading and writing only with the typed track):

<b>A1</b>

- Introduce myself and others, spell my name, give my age, phone number and nationality
- Order food and drink, ask prices, say what I like and don't like
- Ask for and follow simple directions; say what time it is and when things happen
- Describe my daily routine and make simple plans

<b>A2</b>

- Talk about experiences and tell a simple life story with dates
- Shop: ask for sizes, compare items, pay
- Talk about travel plans and give simple opinions
- Say how I feel about things and react to others

<b>B1</b>

- Tell stories about my past, describing background and events
- Deal with most situations when travelling, renting or seeing a doctor
- Make polite requests and ask others to do things
- Give advice and recommendations, and explain my opinions briefly

<b>B2</b>

- Talk in detail about my experience, plans and hypothetical situations
- Take part in discussions, defending a view and reporting what others said
- Make formal complaints and negotiate solutions
- Follow extended speech on familiar topics at natural speed

<b>C1</b>

- Give a well-structured presentation and handle questions
- Use formal and informal registers appropriately at work and socially
- Argue, concede and persuade with nuance
- Follow complex talk and understand implied meaning and humour

## Pace (internal)

- Learner-facing: current level, topics done, lesson and learning hours, Level % and Overall % (above). No target dates, calendar promises or time ranges, even when asked (Motivation above)
- Internal: the bot compares lesson hours and learning hours with the duration table in 13.1 to sanity-check pace. A learner far ahead of the table is checked for rushing (the gates already block it); one far behind gets an offer to change the study plan
- <b>Learning hours</b> = the sum of all Sessions minutes (every type, including self-reported Outside rows); <b>lesson hours</b> = Lesson + Consolidation minutes. Both appear in the weekly summary
